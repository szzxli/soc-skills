WHY SOC-SKILLS

Gap analysis for SOC job seekers — a complement to certs, not a replacement.

About

Certs like Security+ or CySA+, BTL1, and platforms like TryHackMe and Hack The Box teach and test knowledge. soc-skills answers a different question: given the work you can actually show, what are you still missing for a SOC analyst role, and where do you learn it? It grades your lab write-ups and code against a public rubric — 8 SOC skill domains mapped to the NIST NICE framework, with levels you can only earn with evidence.

  • Know where you stand: a level per domain (L1 → L2), each one tied to the file or report that earned it — ready to walk through in an interview.
  • Know what to build next: a gap analysis spells out what's missing for the next level, domain by domain — with links to TryHackMe, LetsDefend, CyberDefenders, MITRE ATT&CK and more.
  • Show it, don't claim it: a résumé one-liner, a printable one-pager, and a hash-checked profile file (it proves the file is unchanged, not that it's true). Runs in your browser — no soc‑skills account needed.

METHOD · LIMITATIONS

How far to trust the scores

Rubric v1.3

Current rubric: v1.3 (2026-10-20), the version the live grader and new packages use. Read the rubric · domain definitions.

Changelog

  • v1.3 · 2026-10-20 — adds D8 AI agent security & governance (8 domains). D1–D7 criteria and grading rules unchanged.
  • v1.2 · 2026-10-17 — prompt-injection resistance (evidence is treated as data) + calibration anchors.
  • v1.1 · 2026-10-16 — behavioral (process) scores. The stored example and sample profile were graded with this version.
  • v1.0 · 2026-10-15 — first rubric and grader.

Older packages still verify; the Verify page links each package to the rubric text of the version it names.

Limitations

  • Small, self-made validation set. The rubric was checked on the author's own 5 home-lab projects, against the author's own ratings with the author's own rubric. The reported 14/15 agreement is AI-vs-author, not AI-vs-independent experts.
  • No human-rater comparison yet. No SOC practitioner has blind-rated the samples, so there is no inter-rater reliability data (e.g. agreement between two humans, or human vs AI).
  • AI grades can vary between runs. Free and small models can give different levels for the same evidence. Run-to-run variance has not been measured; the evaluator-independence results in the repo are illustrative, not measured. Re-run and compare before relying on a grade.
  • Evidence is taken at face value. The grader reads what you paste; it does not run your code or confirm you did the work. Verify in an interview or work sample.
  • Not a certification. Levels are advisory. They don't replace Security+, CySA+, BTL1 or hands-on platforms — they point you at what to learn next.

FAQ

Questions new users ask

7 answers
Does this replace Security+, CySA+, BTL1, TryHackMe or Hack The Box?
No — it complements them. Certs and platforms teach and test knowledge; soc-skills is a gap analysis of the work you can show. It tells you what's missing for a SOC analyst role and links to where to learn each gap (TryHackMe SOC Level 1, LetsDefend, CyberDefenders, BTL1, CompTIA objectives, MITRE ATT&CK).
Is this a certification?
No. Grading is advisory and evidence-based. soc-skills is not affiliated with or endorsed by NIST, NICE, CompTIA, Security Blue Team, TryHackMe, Hack The Box or any employer. L3 (production) is never self-awarded.
Do I need an account or an API key?
No account, ever. The example, the self-assessment, the lab cards and the Verify page need no key. Only live AI grading needs your own key — free OpenRouter models cost $0.
Where does my data go?
Nowhere. Everything runs in your browser and history stays on this device. Your evidence and key are sent only to the API provider you choose, and only when you click Grade. Page views are counted anonymously with GoatCounter — no cookies, and nothing you type.
What do the levels mean?
L1 = guided · L1+ = beyond L1, short of L2 · L2 = independent hands-on, with scope (lab / synthetic / reconstructed) · L3 = production, never self-awarded.
What does a verification package prove?
Only that the file is unchanged since its SHA-256 hash was made, and which rubric version it claims. It is not a signature: it doesn't prove the content is true or who made it. Posting the hash in a public GitHub gist adds a dated public record. Try the Verify page.
How reliable are the scores?
Unproven so far: the rubric has only been checked on the author's own projects, with no independent human raters yet, and AI grades can vary between runs. Read the limitations — and help validate if you work in a SOC.
